Gluetun

Behind a VPN with a forwarded port, the address friends reach you on changes on every reconnect. Point this at gluetun's control server and sharerr resolves its public IP and forwarded port from there, re-announcing and rewriting torrents when they change — instead of trusting the static address above.

{% call locked("gluetun.enabled") %}{% endcall %}

Unticking this pauses polling without losing the control server URL below — useful for a temporary hold, since re-enabling later needs nothing retyped.

{% call locked("gluetun.control_url") %}{% endcall %} {% if gluetun_api_key_set %} {% endif %}

Required since gluetun v3.40, which made apikey the default control server auth — an unkeyed request now gets a bare 401. Find or set it in gluetun's own config under CONTROL_SERVER_AUTH (or the roles section of its auth config file).

{% call locked("gluetun.poll_secs") %}{% endcall %}

The poll is the safety net; for reconnects to be picked up in seconds, set gluetun's VPN_PORT_FORWARDING_UP_COMMAND to hit /gluetun/refresh on this instance. Setting VPN_PORT_FORWARDING_DOWN_COMMAND to hit /gluetun/down too means a port that just went away is dropped immediately rather than kept as a stale fallback until the next poll finds out on its own.

Which port carries the lighthouse's routes. Its own image and port (sharerr-lighthouse) is the deployment the design is built for — self-hosted by anyone, on neutral ground away from any particular library — so prefer that unless running a second container is genuinely not worth it here.

Automatic checks

{% call locked("checks.reachability") %}{% endcall %}

Off by default. When on, the Topology page dials this instance's own advertised tracker and feed addresses and reports whether they answer. A failure here means could not confirm, not "your port is shut" — an instance dialling its own public address is exercising NAT hairpinning, which plenty of working routers simply do not do.
