Tracker

sharerr serves announces itself, from this instance, whichever torrent client seeds. It answers only for torrents sharerr made.

{% call locked("tracker.advertised_host") %}{% endcall %} {% if !gluetun_control_url.is_empty() && gluetun_enabled %}

Not required here: the Gluetun section below is configured to resolve this dynamically instead, and a live observation always wins over whatever this field holds. {% if let Some(observed) = gluetun_last_observed %} It currently advertises {{ observed }}. {% else %} It has not resolved anything yet — leave this set as a fallback until it has. {% endif %}

{% else %}

Required. sharerr cannot guess its own externally reachable address, and a wrong value silently produces torrents nobody can announce to. Behind gluetun with a forwarded port, configure the Gluetun section below instead of typing one here — it resolves and keeps this in step automatically.

{% endif %} {% call locked("tracker.port") %}{% endcall %} {% call locked("tracker.advertised_url") %}{% endcall %}

For reverse-proxied or IPv6 setups: a full base URL with scheme and any path prefix. When set, it wins over the host and port above.

{% if tracker_token_set %} {% endif %}

When set, the token is embedded in every announce URL, so holding the .torrent is what grants the right to announce. Changing it invalidates torrents already published — leave it alone unless you mean to cut off existing peers.

sharerr is serving its own tracker on this instance.

Lighthouse

Rendezvous for a friend whose address rotated while yours did too, so gossip alone has no path back — see docs/roadmap.md's "The lighthouse". This runs the lighthouse service itself as extra routes on one of sharerr's own listeners, for an operator who would rather not run a second container; sharerr does not yet report itself to a lighthouse or query one for a quiet friend, so enabling this only makes the service available, not yet used.

{% call locked("lighthouse.enabled") %}{% endcall %} {% call locked("lighthouse.mount") %}{% endcall %}

Which port carries the lighthouse's routes. Its own image and port (sharerr-lighthouse) is the deployment the design is built for — self-hosted by anyone, on neutral ground away from any particular library — so prefer that unless running a second container is genuinely not worth it here.

Gluetun

Behind a VPN with a forwarded port, the address friends reach you on changes on every reconnect. Point this at gluetun's control server and sharerr resolves its public IP and forwarded port from there, re-announcing and rewriting torrents when they change — instead of trusting the static address above.

{% call locked("gluetun.enabled") %}{% endcall %}

Unticking this pauses polling without losing the control server URL below — useful for a temporary hold, since re-enabling later needs nothing retyped.

{% call locked("gluetun.control_url") %}{% endcall %} {% if gluetun_api_key_set %} {% endif %}

Required since gluetun v3.40, which made apikey the default control server auth — an unkeyed request now gets a bare 401. Find or set it in gluetun's own config under CONTROL_SERVER_AUTH (or the roles section of its auth config file).

{% call locked("gluetun.poll_secs") %}{% endcall %}

The poll is the safety net; for reconnects to be picked up in seconds, set gluetun's VPN_PORT_FORWARDING_UP_COMMAND to hit /gluetun/refresh on this instance. Setting VPN_PORT_FORWARDING_DOWN_COMMAND to hit /gluetun/down too means a port that just went away is dropped immediately rather than kept as a stale fallback until the next poll finds out on its own.
